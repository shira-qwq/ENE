# 新项目启动入口

将空白基座 clone 到独立目录；项目自己的愿望、内容和历史只保存在这个目录的本地 Git，默认不向公开模板仓库 push。不要在 ENE 原维护目录内创建新项目。Node.js 与 Git 是本地查看所需环境；PI 可选，配置标签不代表已经安装或认证。

## 给新窗口的启动指令

在这个目录使用 ENE 创建项目。先读 README.md、AGENTS.md、docs/ENE_PARADIGM.md 和 Discussion / Builder 合同，核对 WANT.json、results/CURRENT.json、当前卡/checkpoint 与 Git。先确定要产出什么、最小文件布局、交付入口、验证方式和恢复边界，再开始已授权的施工。沿用 Home，不创建第二份事实或管理系统；新项目从空状态开始，不继承旧项目接受记录。普通技术选择自行决定，真实业务分歧才问用户。

## 两种开始方式

- 新领域项目：先在一张施工卡里约定领域内容、产物与必要说明放哪里；Home 展示愿望和交付，复杂内容在作品自己的页面实现。不要把正文、数据库等领域数据强塞入 WANT。
- 复制或修改 ENE：先记录继承的 Git 保存点、必须保留的原则、拟改 UI/协议、验证和回退范围。候选规范在新副本内维护，不覆盖原冻结版本；稳定后才能作为另一个可复用基座。

## 接入原型与重构

不把旧代码、素材、数据统统放入 docs。只作参考的原型默认留在原处，在当前卡记录路径、参考范围与不可继承部分；需要移入时记录来源、目标和此后唯一维护位置。要重构的项目先保存原版本，沿用其实际目录，在独立分支或副本内按卡重构；明确保留的行为、替换范围、交付、验证与回退。无法运行或没有 Git 的原件先做不覆盖原件的本地副本/保存点，如实记录缺失证据，不宣称已有可靠基线。没有一条适合所有旧项目的整包搬运命令。

文件布局一次写进已有入口或当前卡，不另建目录树文档。默认沿用已有职责目录；不按日期、对话或研究轮次新增文件夹。更新同一问题的现有文档，阶段历史由 Git 保存；独立问题才新增必要文件。新增目录必须有实际产物和明确用途，在原约定中说明即可。冻结文档说明范围，Git 保存代码与已纳入版本控制的数据；密钥、运行进程与未纳入 Git 的领域数据须另行明确保存边界。

## 多张卡与不同模型

可一次准备多张有独立范围的卡，写明授权、前置依赖、执行模型、允许修改的位置与验证；尚未授权的候选只留在愿望或讨论记录，不放入可执行卡。卡片存在不自动启动、不等于自动队列；本版同一工作目录一次执行一张，完成或保存 checkpoint 后再接下一张。不同模型可按同一卡串行接手，不要求重新生成项目事实。

若要同时比较不同模型的原型，另行明确授权并使用独立副本/工作目录，各自保留卡、checkpoint、回执与运行配置；有后端时还需独立数据和端口。仅分到不同模块文件夹不能隔离共享配置、Git 和运行状态，不允许多个 PI 共用同一工作目录。现有启动器与工作状态卡没有多实例调度/汇总承诺。结果交回 Discussion，在主项目串行整合、验证并记录来源；候选原型不自动成为已接受成果。本约定不授权现在启动任何 Builder，也不增加调度平台。

## 遇到问题如何处理

### 生成数据的保存约定

首次产生数据前，在现有项目入口或当前卡里写清唯一保存位置、哪份是当前事实、是否纳入 Git，以及恢复方法；后续沿用，不按轮次另建目录或维护第二份清单。

- 要保留的正文、用户修改、已接受结果及其必要输入不能当临时缓存。适合 Git 的文本数据随项目提交；敏感内容仅保存在本地或授权的私有位置，不向公开模板推送。大文件、数据库及不适合 Git 的数据记录实际备份位置，不宣称 Git 已保护它们。
- 能从已保存输入重新生成的缓存可不进 Git；在原约定里注明重建方式。无法证明可重建的数据默认保留；“模型可以再生成一次”不等于能恢复相同内容。
- 新生成结果先作为候选保存，校验成功后才更新当前指针；不直接覆盖已接受内容。失败或中断保留此前可读版本和短 checkpoint，只提交完整结果，不把半成品标成当前交付。
- 覆盖、删除、批量转换或数据库迁移前，先建立可用保存点/一致性备份，记录它对应的代码版本和数据范围。需要恢复时先保存当前新数据，再按明确范围恢复；不默认清空数据库、不因代码回退而覆盖后来生成的成果。无法确认备份可用时停止破坏性数据操作，交 Discussion 处理。

### 依赖与凭据的配置约定

接手模型先核对当前卡实际需要的运行环境、项目依赖和可用配置。已有能力直接用；缺什么、影响哪一步、怎样配置写在已有入口/卡中，不另造配置平台。PI 是可选 Builder，未配置时可由 Discussion 直接施工，不显示虚假的 PI 运行状态。

项目依赖沿用项目自己的清单、锁文件与安装方式，不为解决一个缺口默认升级全局环境。安装/认证按已有授权执行；涉及账号登录、费用或全局环境改变且未获授权时才请求用户。凭据由使用者在本机配置，只维护无秘密的样例和字段说明；不写入回执、投影、日志或公开 Git。未知配置与凭据不覆盖，不为测试输出秘密。

缺配置只暂停依赖它的操作，继续已授权的独立工作；回执明确未验证项。不能以空结果或模拟成功替代真实调用。本节是项目启动约定，不代表当前任务已获安装或调用外部服务授权。

- 缺运行环境、凭据或依赖：记录缺口，不伪造运行成功；能独立完成的工作继续，需要安装或认证的操作按实际授权处理。
- 当前文件、卡片与 checkpoint 矛盾：以实际文件/Git 核对，保留未知修改；无法判断的事实交 Discussion 定向处理，不整仓重写。
- 工具失败或反复修复仍失败：保存已做、未验证项、错误与下一步，返回 FAILED 或 NEEDS_CODEX，停止扩大范围。
- 产品方向有分歧：保存最小候选与依据，返回 OWNER_DECISION；不能替用户接受。
- 中断/停止：保存短 checkpoint，下一窗口从卡、文件与 Git 接手；没有活进程证据不能显示运行中。
- 后端、数据和多版本：卡片写清验证与数据恢复边界；多实例另行隔离代码、数据、端口和进程。现有对比页只展示可打开的交付，不自动提供实例编排，也不把 Git 回退等同于数据恢复。

启动命令见 README；修改权威文件后重建投影。Home 查看服务关闭用其启动终端 Ctrl+C；页面 Stop 只停止对应 Builder 工作。
