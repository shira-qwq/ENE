# ENE 薄项目范式 · 1.0

这份文件保存可复用的工作原则，不保存每个项目的运行状态。项目就是本地目录和实际文件；聊天与模型可以替换，接手不以 Skill 是否加载为条件。Owner 只看需要判断的愿望、交付和工作状态，其余维护由 AI 承担。

## Owner 如何使用
在 Discussion 入口提出、修改、暂缓或否定愿望。Home 负责筛选愿望、显示已有回应与交付，打开作品或放入独立 A/B 对比。资料按需阅读，后台工作能看见、能停止，停止记录保留。用户不需要维护任务卡、运行协议或保存点。
愿望不是自动施工授权；Builder 完成不是 Owner 接受。AI 提议经明确采用才成为用户的批准意图。不要把“完成了一项技术检查”写成“用户喜欢这版”。

## 文件只分必要职责
- 意图：沿用 WANT.json，记录短摘要、实际状态、说明和已知任务关联。新愿望记录 created_at，修改保留它并更新 updated_at；旧愿望只显示 Git 最早可查保存。
- 当前事实：领域项目自己的内容/数据/代码及 results/CURRENT.json 的交付指针。范式不规定故事如何创作或项目用什么框架。
- 授权与结果：changes/active|done/<任务>.md、receipts/<任务>.md。回执写交付位置、保存版本、已做/欠缺、实际证据与边界，不复制整个源码。
- 恢复：.ai/work/<任务>.json 是短的当前 checkpoint，覆盖更新已做/正在做/下一步/未验证项，不作无限日志。活进程、密钥和本机运行记录不进 Git。
- 历史：Git 保存有意义的已验证阶段；需要看旧作品时只读保存版本，不先改当前工作目录。
- 页面：results/ 下唯一 renderer、home.config.json 与可重建投影。配置控制来源/标题/默认展示，不能签接受或成为第二份事实。

项目开始前只约定实际需要的目录：产品/内容、产物、任务、回执/必要说明、临时运行位置。项目资料仅映射 changes、receipts、显式纳入的 docs 子目录；不把整棵源码、密钥或运行目录作为资料展示。不需要空建多层文档。

## Discussion 与 Builder
配置一次真实入口与可用模型，除非 Owner 要求更换，角色保持稳定。默认 ENE 为 Codex Discussion 与 PI Builder；配置展示不保证另一台电脑已安装这些能力。
Discussion 维护用户意图、授权和真实接受；把可执行范围交给一张任务卡。Builder 先读当前文件/卡/checkpoint/Git，施工、留下结果与证据、保存进度后停止。两者都维护职责内文档。不同模型按同一卡串行接手，不同时改同一项目。Discussion 发现文件损坏或事实矛盾时可定向核对纠正，不把每项成功交付变成全仓源码审查。
强模型先看证据/结果/相关差异，必要时才看源码。弱模型也能按短卡和真实文件施工。证据已有就引用，未知就明确未知，不为页面好看编造阶段或历史。

## 保存、恢复与有限回退
保存点围绕有意义的阶段，非每次操作。中断后看当前卡、checkpoint、实际 Git/文件和必要证据，修正过期状态再继续。
看版本优先只读 Git；回退先保存当前修改、说清回退代码/领域数据/意图的范围，再开独立 checkout 或恢复指定文件。本机配置与运行状态不是 Git 快照，回退代码不自动恢复后端数据或进程。需要的当前交接文件按范围携带，不承诺 clone 恢复活进程。
前端可直接 A/B 打开；后台修改只提供用户需要判断的页面或文本证据。后端多版本同时运行须另行隔离代码、数据、端口和进程；ENE 1.0 尚未提供实例编排。Stop 控制 Builder，不能假装同时关闭作品后端。

## 两种复用
普通项目：沿用核心职责、一次文件布局约定和同一页面外壳；按领域需要薄映射内容，复杂编辑在作品自身实现。不要为了沿用 Home 把所有领域数据改成 WANT。
复制或修改 ENE 本身：除了普通任务卡，必须写明所继承的冻结版本、保留的核心规则、候选改动、影响的 UI/协议、验证与回退范围。保持事实权威单一、Owner 接受隔离、原历史可追溯；修改范式本身先作为候选，不悄悄覆盖冻结规范。这是额外约束，不是第二套引擎。
不依赖 Paperclip，不增加数据库、队列平台、常驻监工或 Skill 必装条件。第一版冻结先落地，其他项目迁移和领域流程另行授权。
