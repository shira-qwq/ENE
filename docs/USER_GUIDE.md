# ENE 用户使用说明

你只需要提出愿望、查看交付、作出决定。模型负责任务卡、文件维护和保存点。以下句子发给能访问项目本地目录的 Discussion 模型即可；它们是自然语言示例，不是需要背下来的特殊命令。

## 第一句话怎么说

新建项目：
> 用这个 ENE 空白基座创建【项目目标】，按 docs/PROJECT_START.md 开始，先确定文件布局和最小交付，再做原型。

接手、重构现有项目：
> 用 ENE 接手【本地项目路径】，目标是【希望怎样改】；先保存原版本、核对实际入口，保留【不能丢的功能】，不要默认搬目录或整仓重写。

复制、改造 ENE 自身：
> 在独立副本里以当前 ENE 保存版本为基线，做一个【用途】的底座；保留文件即事实、愿望与接受分离和可恢复约定，先列出候选改动并做原型，不覆盖原项目。

还不清楚目标：
> 我想做【大概的事情】，先帮我整理愿望和第一个值得看的交付，现在不要施工。

## 什么时候可以开始原型

当你和 Discussion 已明确“先看什么、哪些不能改、做到什么就停”，就可以说：
> 按刚才确定的范围做一个最小原型，完成后给我入口和这次要看的点。

不需要先把所有功能想完。原型不等于正式采用；看到后可以继续修改、拒绝或暂缓。想进入正式施工时说：
> 我认可【具体原型版本】，把它整合进正式项目，保留【已有功能】，验证并保存。

## 平时怎么提出愿望和决定

- 新愿望：“我希望【效果】，先记下来，暂时不要施工。”
- 修改愿望：“把【愿望编号或标题】改成【新意思】，其他愿望不变。”
- 暂缓：“【愿望】先暂缓，原因是【原因】。”
- 不采纳：“【愿望或方案】不采纳，保留这个决定。”
- 看进度：“现在做到哪里？已完成什么，还差什么，下一步是什么？”
- 看交付：“打开【任务/版本】的交付，告诉我这次应该验收什么。”
- 接受：“我接受【明确版本】的【范围】，记为后续基线。”没有明确表态，技术完成也不会替你接受。
- 换模型：“下一张任务卡由【模型】施工，沿用当前项目文件和约定。”模型实际可用性由本机配置决定。

## 暂停、恢复和回退

后台 Builder 正在运行时，可点击页面的“停止后台工作”；它只控制这项 Builder 工作，不关闭 Home 或作品后端。按钮未出现时，不代表可以通过一句聊天保证另一个进程立即停止：让 Discussion 核对实际工作并保存进度。需要关闭 Home 服务，在启动它的终端按 Ctrl+C。

换窗口或中断后：
> 按项目入口、当前任务、checkpoint 和 Git 接手，先告诉我实际做到哪里，再继续原授权任务。

想回退时：
> 先保存当前修改，我想回到【版本】的【代码/内容/界面范围】；保留后续生成的数据，说明恢复范围后再操作。

## 页面怎么看

- 愿望：筛选和选择愿望，看下面的回应与交付。愿望内容和决定通过 Discussion 修改；网页筛选、字号等只改变显示。
- 对比：选择两份有入口的交付，上下或左右查看。后端结果需有页面或可读证据才能展示，不自动启动两个后端实例。
- 项目资料：阅读使用说明、约定和任务回执。模型从本地权威文件生成投影，源文件更新后由模型刷新；这里不是第二份事实。
- 工作状态：查看最近后台记录；停止和结束记录保留。没有运行证据就不会把旧记录当作活进程。

首次打开可以对模型说：“启动这个项目的 Home，把本地地址给我。”本机需有 Node.js 和 Git；PI、模型凭据等由使用者配置，缺少时会说明影响，不会假装成功。新项目的内容和历史留在自己的本地 Git，默认不推回公开模板仓库。
